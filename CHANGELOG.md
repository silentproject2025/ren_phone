# Changelog

## Unreleased
- Changed: on the Aether Board, the WROOM Bluetooth co-processor link now uses the real UART2 pins (AETHER_UART2_V1): S3 GPIO41 (TX) to WROOM GPIO16 (RX2), S3 GPIO42 (RX) from WROOM GPIO17 (TX2). It is a separate build, `bt_wroom_aether_merged.bin` (`-DRP_BT_ONLY=1 -DRP_LINK_UART2=1`), also in the web flasher; the regular WROOM and ESP32-CAM builds keep GPIO 13/14. The S3 firmware is unchanged (its link pins are still 41/42). Because GPIO16 is not an RTC pin, *power off* on this build uses light sleep with a GPIO wake-up (then restarts) instead of deep sleep. Not yet compiled or tested on a device. Script: `apply_aether_uart2_patch.py`
- Added: progressive JPEG covers in the Music app (COVER_PJPG_V1). When JPEGDEC rejects a JPEG, the cover is decoded with `stb_image` (JPEG only, memory in PSRAM, images over 700 000 pixels skipped) and averaged down to the record label. Optional: it is built only if `firmware/phone/stb_image.h` exists (download it from github.com/nothings/stb); without the file nothing changes. Not yet compiled or tested on a device.
- Changed: Music app redesign, softer and rounder, with the spinning record back instead of the poster (MUS_DISC_V1). The geometric poster is gone: the cover is a black vinyl record that spins while a song plays and stops when paused. Its centre label is the real cover (it spins with the record) or, when there is no cover, a label coloured from the title with two turning arcs. Soft shadow and accent glow, grooves and a two-layer sheen. Chips, list rows and bottom buttons are rounded pills (no hard outlines, no row separators); progress and volume are rounded bars with a round knob; the Play button is a round button with a soft halo; equalizer bars are rounded; status marks are dots. Same layout and touch areas as before. Not yet compiled or tested on a device.
- Fixed: songs from the Online page (Jamendo / Audius) never showed a cover, because the cover code only read ID3 tags and files next to a local song (COVER_NET_V1). Online tracks now carry the cover URL (Jamendo `image`, now requested at 200 px; Audius `artwork` 150x150, else 480x480). About 2.5 s after the stream starts the app downloads it on the existing Online worker task (checks that internal RAM has a 24 KB free block first, else the record is kept), and decodes it on the music task, so the record label, the player accent colour, the big-cover page and the Home / Lock Screen card all show it. Limits: baseline JPEG or PNG only, images over 320 KB are skipped, a result for a song that is no longer playing is dropped. Local MP3 files still only show a real cover if the file has an ID3 cover or a `cover`/`folder`/`album`/`front` image beside it; otherwise the record is shown. Files: `musicbt_renphone.ino`, `musjam.h`, `jam_core.h` (`JamTrack` has a new `img` field)
- Improved: the Music app shows a real cover far more often, not just the generated poster (MUS_COVER_V2). Cover sources, in order: the ID3 tag (JPEG **or PNG** now; before only JPEG), then an image next to the song (`<song name>.jpg/.jpeg/.png`, then `cover`, `folder`, `album` or `front` with `.jpg/.jpeg/.png` in the same folder; works on SD and on FFat), and only then the geometric poster. The player accent follows the cover: the hard block behind it, the status label, the equalizer, the progress line and the Play button use the average colour of the cover (made brighter and kept readable against the theme background). Tap the COVER in the player to open a big-cover page (cover up to 150-190 px, title up to 3 lines, progress, previous / play / next); tap anywhere else or the back gesture closes it. Tapping the title still plays or pauses, and swiping left or right still changes song. The music card on Home and the Lock Screen shows the real cover of the playing song instead of the coloured disc. Limits: progressive JPEG is still not supported (JPEGDEC), images over 1.5 MB are skipped, PNG decode is not downscaled smoothly. Only drawing, cover-loading and touch code changed; no change to playback or the CAM link. Not yet compiled or tested on a device. Script: `apply_music_cover_patch.py`

- New: Audius as a second source for online music (AUDIUS_V1). In the Music app, Online page, a chip next to the search box switches between *Jamendo* and *Audius*; the choice is saved (NVS `music`/`jsrc`). Audius needs no API key, so it is the default when the build has no `JAM_CLIENT_ID`. Search uses `/v1/tracks/search`, the genre chips use `/v1/tracks/trending` (week) with the genre Pop / Rock / Lo-Fi / Jazz, and playing a track fetches `/v1/tracks/<id>/stream`, which redirects to the MP3. Tracks that are not streamable or are stream-gated are skipped. Results use the same list, ranking and playback path as Jamendo (speaker and Bluetooth). Audius streams are usually 320 kbps, so with *Output: BT* the 128 KB ring holds about 3 seconds instead of 8 and a weak Wi-Fi may cause gaps. The response buffer in PSRAM grew from 128 KB to 256 KB. Also fixed: a non-ASCII letter at the very end of a title or artist name was dropped (`jamUnescape`), for both sources. The parser is tested on a PC; the network and UI parts are not yet compiled or tested on a device. Script: `tools/patches/apply_audius.py`
- New: Aether Board reads the battery voltage through a 10k + 10k voltage divider on GPIO1 (BATT_ADC_V1). `vBat = pinVoltage * 2.0 + 0.032`, clamped to 0-5 V, 16 ADC samples averaged once per second and smoothed. It is used only when no INA219 is detected (INA219 still wins), so other boards are unchanged. The percentage comes from the voltage curve; charging is not detected and the Battery app still shows *Sensor offline* because it needs the INA219. Because GPIO1 was the SDA of the sensor bus (MPU6050/INA219) on this board, that SDA moved to GPIO21 (override with `-DRP_SENS_SDA=<pin>`); a build error now stops a clash between the battery pin and the sensor or touch pins. Not yet compiled or tested on a device. Script: `apply_aether_vbat.py`
- Improved: searching online music (Jamendo) works with part of a title (JAM_PARTIAL_V1): typing *ab* finds *ABCD*. The search uses Jamendo's `namesearch` (matches anywhere in the track name, most popular first) instead of whole-word `search`; if that finds nothing it falls back to the normal search (artist names, tags, whole words). Results are re-ordered on the device: title starts with what you typed, then a word starts with it, then it appears inside the title, then it matches the artist. Up to 40 results are fetched (was 20) so less popular tracks have a better chance; the response buffer is 128 KB in PSRAM. A very short query such as *ab* matches a lot of tracks, so a longer one (*abc*) finds a specific song more reliably. `jam_core.h` ranking is tested on a PC; the network part is not yet compiled or tested on a device. Script: `apply_jam_partial.py`
- New: online music (Jamendo) can now play through the Bluetooth TWS earbuds, not only the speaker (BT_NET_V1). With *Output: BT*, tapping an online track starts a download task that fills the 128 KB PSRAM ring (the one the AVI player uses), and the music task sends it to the ESP32-CAM over RPLink, which decodes it and plays it over A2DP. The ID3 tag at the start of the stream is dropped (its cover art would only waste decoder time). Pause, volume, next/previous, auto-next and the earbud buttons work like for SD tracks. The *Online butuh output SPK* restriction is gone. The speaker path is unchanged. Opening an AVI video stops the online track (they share the ring). Not yet compiled or tested on a device. Script: `apply_bt_net.py`
